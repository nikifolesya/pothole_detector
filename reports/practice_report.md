# Отчет по практике

## Тема

Сравнение архитектур для детекции дефектов дорожного покрытия на изображениях и видео.

## Цель

Разработать воспроизводимый пайплайн компьютерного зрения для обнаружения дорожных ям и близких дефектов, сравнить несколько архитектур детекции, выбрать пригодное для прикладного использования решение и оформить его как сервис инференса.

## Объект и предмет исследования

Объект исследования: изображения дорожного покрытия с дефектами.

Предмет исследования: методы детекции объектов для локализации дорожных ям, трещин, участков повреждения, люков и визуально похожих классов.

## Входные и выходные данные

Вход: RGB-изображение или кадр видео.

Выход: список найденных объектов с классом, уверенностью и координатами bounding box в формате `xyxy`; аннотированное изображение; запись в историю запусков.

## Данные

Использован датасет Roboflow `pothole-detection-2-zvaru`, version 6, license CC BY 4.0.

| split | images | labels | objects | empty labels |
| --- | ---: | ---: | ---: | ---: |
| train | 5325 | 5325 | 13022 | 13 |
| valid | 4943 | 4943 | 12042 | 18 |
| test | 4070 | 4070 | 10329 | 17 |

В датасете 16 классов. Наиболее важные для прикладной задачи классы: `Pothole`, `medium-pothole`, `risk-pothole`, `pothole_water`, `crack`, `damage`.

Потенциальные ограничения данных: неоднородная разметка близких классов, сильный дисбаланс, разная съемочная перспектива, отличия освещения, часть классов фактически описывает один и тот же тип дефекта разными именами.

## Рабочая гипотеза

Легкие YOLO-модели должны дать лучший баланс качества и скорости для сервиса, а RT-DETR может повысить качество на сложных сценах ценой большего времени инференса. Увеличение входного разрешения должно улучшить обнаружение малых ям, но ухудшить latency.

## Пайплайн

1. Проверка датасета и YOLO-разметки.
2. Обучение baseline YOLOv8n.
3. Обучение YOLO11n как современной легкой модели.
4. Абляция входного разрешения YOLO11n: 640 против 960.
5. Обучение RT-DETR-L как альтернативы на transformer-based detector.
6. Экспорт лучшей модели в ONNX и сравнение скорости инференса.
7. Анализ ошибок: FP, FN, неверные классы, локализация, малые объекты, сложный фон.
8. Развертывание FastAPI-сервиса.

## Метрики

Основные метрики детекции:

| метрика | смысл |
| --- | --- |
| `mAP@0.5` | качество детекции при IoU 0.5 |
| `mAP@0.5:0.95` | более строгая интегральная метрика |
| `precision` | доля корректных срабатываний среди предсказаний |
| `recall` | доля найденных объектов среди объектов разметки |
| `FP/FN` | ложные срабатывания и пропуски |
| latency | среднее время инференса |
| weights size | размер артефакта модели |

Для магистерского уровня дополнительно оцениваются малые объекты, влияние threshold/NMS, устойчивость к сложному фону и качество после экспорта.

## Деплой

Реализован FastAPI-сервис:

| endpoint | назначение |
| --- | --- |
| `/health` | проверка состояния |
| `/predict` | инференс одного изображения |
| `/batch_predict` | пакетный инференс |
| `/stats`, `/metrics` | статистика и история запусков |

История запусков сохраняется в SQLite: входной файл, backend, latency, число детекций и JSON-результат.

Проект содержит `Dockerfile` и `docker-compose.yml`. Запуск:

```bash
docker compose up --build
```

## Анализ ошибок

В рамках smoke-test сохранен пример инференса `outputs/smoke_test_annotated.jpg`. Для расширенной сдачи стоит добавить минимум 10 примеров в `outputs/annotated/`: 5 удачных и 5 ошибочных.

Ожидаемые типы ошибок:

1. Ложные срабатывания на тенях, заплатках асфальта и пятнах воды.
2. Пропуск малых дефектов при низком разрешении.
3. Смешение классов `Pothole`, `medium-pothole`, `risk-pothole`.
4. Неполная локализация вытянутых трещин.
5. Ошибки на частично перекрытых или размытых объектах.

## Вывод

Проект оформлен как воспроизводимый практический пайплайн. Подготовлены датасет, конфиги экспериментов, два реальных fine-tuning прогона, ONNX-экспорт, сервис инференса, Docker-запуск, история запросов, smoke-test и отчет. На CPU лучший результат показал YOLOv8n quick: `mAP50-95=0.06245`, latency около 51 ms/image в PyTorch и 11 ms/image в ONNX Runtime smoke-test. Для дальнейшего улучшения качества рекомендуется запустить полные конфиги на GPU и отдельно проверить объединение близких классов `Pothole`, `medium-pothole` и `risk-pothole`.
